# 瀏覽器 e2e 測試方法

> 通用方法紀錄，與 imgforge 本身功能無關；案例取自 2026-11-12 imgforge 部署至 claude.ai 的實測。

## 1. 是什麼

由 Claude Code 透過瀏覽器擴充（Claude in Chrome）**像真人一樣操作網頁**：部署 → 觸發 → 在真實環境執行 → 收集結果 → 清理。驗證的是「整條使用路徑」，不是程式邏輯。

| 層級 | 方式 | 能抓到 |
|---|---|---|
| 單元測試 | `unittest` / `pytest` | 邏輯、錯誤訊息 |
| 本機 e2e | 在 Claude Code 對話中實際使用工具/skill | 觸發、AI 照說明寫輸入的成功率、token |
| **瀏覽器 e2e** | 操作真實網站／服務 | 部署流程、遠端環境限制、他模型的行為 |

## 2. 何時用

- 要發布到**無法本機模擬**的環境（雲端沙箱、SaaS 後台、別人的瀏覽器流程）。
- 發布前最後一關，且使用者**明確要求**。
- 不用在日常開發：慢（數分鐘/次）、結果不固定、會動到帳號。

## 3. 流程

1. **確認授權**：會動到哪個帳號、會新增/刪除什麼，先告知並取得同意。
2. **準備產物**：本機先打包並通過單元測試／本機模擬（乾淨 venv 解壓執行）。
3. **開分頁**：`tabs_context_mcp` → 用自己建立的分頁，不碰使用者既有分頁。
4. **部署**：`find` 找元素 → `file_upload` 上傳（不要點檔案按鈕，會開原生對話框）→ 截圖確認預覽。
5. **觸發**：在目標頁輸入測試指令；**明確要求對方貼出原始輸出**，方便判讀。
6. **觀察**：`wait` + `get_page_text` 讀文字；展開工具步驟看 Request/Response 原文；`zoom` 看產出圖。
7. **記錄**：結果寫進文件（環境、輸入、輸出、問題），commit。
8. **清理**：刪除測試用部署與對話（永久刪除前再確認）、關閉分頁。

## 4. 踩過的坑

| 問題 | 對策 |
|---|---|
| 在輸入框按 Enter 沒送出 | 截圖確認，改點送出鍵 |
| `find` 拿到的 ref 頁面重繪後失效 | 動作前重新 `find`，或改用座標 |
| 檔案上傳只接受本機可存取路徑，單次 <10MB | 產物放專案或 scratchpad 內 |
| 網頁內的確認框（非 JS alert）可正常點擊；JS `alert/confirm` 會卡住擴充 | 避免觸發 JS 對話框 |
| 遠端回覆**不照指示**（要求貼原文卻只轉述） | 展開工具步驟直接讀 Response |
| 遠端用的模型與本機不同（例：Sonnet Low），結果不固定 | 視為抽樣，不當作穩定斷言；關鍵行為多跑幾次 |
| 上傳的 skill 會**同步回 Claude Code**，造成本機重複載入 | 測完立即刪除 |
| 每步單獨呼叫很慢 | 可用 `browser_batch` 串連多個動作 |

## 5. 檢查清單

- [ ] 使用者已明確要求並同意會動到的帳號/資料
- [ ] 本機測試與模擬已通過
- [ ] 測試指令要求輸出原文
- [ ] 讀取工具步驟的 Request/Response，而非只看摘要
- [ ] 結果寫入文件並 commit
- [ ] 測試部署與對話已刪除、分頁已關閉

## 6. 案例：imgforge → claude.ai

| 步驟 | 結果 |
|---|---|
| 上傳 `dist/imgforge.zip` 至「客製化 → 技能 → 上傳技能」 | ✅ 預覽正確、自動啟用 |
| 新對話請求「64px 寵物 icon + 4 幀 GIF，先跑 check 並貼原文」 | skill 自動載入 |
| `check` 原文 | `backends: 無`；沙箱無 SVG 後端、預設不可 pip |
| 降級 | ✅ 依 SKILL.md 改走 `.pix` 產出；過程中行數算錯一次後重做 |
| 結論 | 本機測不出的三件事：遠端無後端、無網路、他模型寫輸入的錯誤率 |
| 清理 | 刪除 skill 與測試對話（skill 曾同步回 Claude Code 造成重複） |
